# Как помочь проекту

## Добавить сервис в справочник

Справочник — файл [`skills/subscription-hunter/scripts/services.json`](skills/subscription-hunter/scripts/services.json). Один сервис — одна запись:

```json
{"id": "my-service", "name": "Мой сервис", "category": "Кино", "patterns": ["myservice", "мой\\s*сервис"], "site": "myservice.ru"}
```

- `id` — латиницей, уникальный.
- `patterns` — регулярные выражения, по которым сервис узнаётся в описании операции. Описание приводится к нижнему регистру. Берите то, как сервис **реально** выглядит в выписке, например `OKKO.TV MOSCOW RUS` → `okko`. Следите, чтобы шаблон не ловил чужие операции: `yandex.*plus` — да, просто `yandex` — нет, иначе в подписки попадут такси и доставка.
- `site` — только домен официального сайта, без `https://`. Если не уверены — `null`.
- `store` — `"apple"` или `"google"`, если оплата идёт через магазин приложений.

Добавьте тест в [`tests/test_subhunter.py`](tests/test_subhunter.py), если шаблон может пересечься с другими сервисами.

После изменения справочника пересоберите данные онлайн-версии: `python3 scripts/build_web.py`.

## Банк, выписку которого скрипт не читает

Создайте issue с **заголовками колонок** и одной строкой-примером, где все данные заменены на выдуманные. Не прикладывайте настоящие выписки — это персональные данные.

## Онлайн-версия

Страница — в папке [`docs/`](docs/): `index.html`, интерфейс `app.js` и ядро `subhunter.js`. Ядро повторяет логику Python-скрипта шаг в шаг. Меняете логику поиска — меняйте в обоих местах: тесты сверяют их результаты. Никаких внешних библиотек, шрифтов и запросов в сеть: это запрещено политикой безопасности страницы.

## Проверка перед pull request

```bash
python3 -m unittest discover -s tests
```

Тесты работают на стандартной библиотеке Python; для сверки с онлайн-версией нужен Node.js — без него эти тесты пропускаются.
